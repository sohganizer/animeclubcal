# 学習ログの置き場を足した

このノートは、ルールを追加した変更と同時に書いたものです。

## 依頼の要点

Cursor がこのカレンダーに加えた変更と、そのときの判断を、Obsidian に取り込める形で残す。やることは3つ。常時適用のルールを `.cursor/rules/obsidian-learning-log.mdc` に足す。2026-10-24 15:56 JST の初回コミットから、2026-10-25 13:34 JST の最新コミットまでを git log と diff から読み、同じ形式のノートを数枚作る。`docs/learning-log/README.md` に、Vault `~/Downloads/Grok の 記録/学習/` へ同期されることと形式を短く書く。main へはマージせず、直 push もしない。サイトの表示と既存ファイルの動作は変えない。

## やったこと

`alwaysApply: true` のルールを1枚足した。変更がワークツリーに残るとき、`docs/learning-log/YYYY/MM/<id>.md` を新規ファイルで1枚足す。id は `YYYYMMDDTHHMMSS+0900__cursor-animeclubcal__学習__<8hex>`。front matter は `id`, `type: 学習`, `bot: cursor-animeclubcal`, `at`（JST の ISO）、`tags`, `status`, `source`, `related`。本文の見出しは指定の5つ。既存ノートは編集しない。秘密や個人情報は書かない。ノートを足すたびに README を書き換えない、という停止条件もルールに入れた。

履歴は main 上の7コミットだった。初回は README のみ。その後、`events.json` と `index.html` が1〜2秒差で3組。コミットごとに1枚、計7枚を `status: 追記` で書いた。8桁は各コミット SHA の先頭8桁。時刻はコミットの JST。データノートは JSON をパースして件数とフィールドを比較し、画面ノートは `index.html` の diff を読んだ。当時の依頼文はコミットに無いので、各ノートに無いと書いた。

README には同期先、id、front matter、本文の見出しだけを書いた。

## うまくいった・失敗したこと

サイトのファイルは触っていない。`events.json` が改行無しの1行だと分かり、diff を目で追わずに比較できた。画面とデータが別コミットなので、午後の「今週」の帯を、件数の増減の理由だと誤解せずに分けられた。

復元なので、当時 Cursor が何を頼まれたかは分からない。コミットメッセージは `Initial commit` と `update events.json` と `update index.html` だけである。同じ url の重複や、`status.run` が `extract` の途中のまま公開されていることは diff から見えるが、収集コードはこのリポジトリに無いので、ここでは直していない。

このノートの `source` に、この変更自身のコミット SHA は入れていない。ノートを書いてからコミットするため、SHA はまだ無く、あとからこのファイルへ書き足さない。

## 次から気をつけること（ルール化候補）

- 変更のたびにノートを1枚足し、既にあるノートは開いても書き換えない。
- `events.json` を整形しない。`index.html` の挙動を、ログ作業のついでに変えない。
- データと画面が秒差で別コミットでも、意図が別ならノートも分ける。今回の復元はその分け方にした。
- `run.n` やコミットメッセージを、変更内容の説明として使わない。
